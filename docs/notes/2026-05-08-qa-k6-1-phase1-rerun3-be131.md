## 📊 분석

1. **achieved RPS +28% (vs baseline)**: 의외 — wiring 추가했는데 처리량 ↑. 가능
   원인: (a) BE 부팅 직후 GC/JIT warm-up 안 끝난 상태에서 측정한 baseline 의 cold
   start 효과, (b) Hibernate flush batching 효과 (3 INSERT/tx), (c) MySQL InnoDB
   buffer pool warm-up 누적. 본 부분은 별 검증 필요(반복 측정).
2. **p95/p99/max 대폭 단축**: 같은 부하에서 latency 분포가 크게 좁아짐. 이전
   회차의 long-tail 가 BE warm-up 미완 + JIT 미컴파일된 hot-path 때문이었을 가능
   성. baseline 측정값은 cold start 편향 감안 필요.
3. **Outbox drain backlog**: ingestion peak 416 events/s vs drain 70 events/s →
   backlog 약 6x 누적. 100k+ 이벤트가 PENDING 으로 30분 이상 잔존. 운영 의도
   (transactional outbox = 비동기 처리) 와 정합 — 단 drain 처리량 부족은 Phase
   2/3 scale-out 학습 demo 가치.
4. **CLAIMED = 0 ~ 19** 사이 진동 — SKIP LOCKED 는 정상. publisher tick 간 짧게
   CLAIMED → DONE 전이.
